2. PROBLEMAS DETALLADOS (por prioridad)

==========================
 P0 — CORRECTIDAD / BLOQUEANTES  (deben resolverse primero)
==========================

[P0-1] Lint roto: no hay gate de calidad confiable
  Archivo: src/context/estilosContext.jsx:3
  Problema: el archivo exporta tanto el Context como el Provider; la regla
            react-refresh/only-export-components lo marca como error.
  Impacto: `npm run lint` sale con código 1 → cualquier CI fallaría.
  Acción:  separar en src/context/EstilosContext.js (createContext) y
           src/context/EstilosProvider.jsx (componente), o excluir el archivo
           de la regla de forma explícita y documentada.
  Criterio: `npm run lint` → 0 errores, 0 warnings.

[P0-2] Código muerto engañoso
  Archivo: src/useEstilos.jsx (20 líneas)
  Problema: hook duplicado, con nombres de clave distintos (Color vs color),
            importado por NADIE. Es una bomba de confusión para el siguiente
            que toque el proyecto.
  Acción:  eliminarlo. Si se quiere conservar la idea, moverlo a
           src/hooks/useEstilos.js implementándolo encima del Context.
  Criterio: `grep -r useEstilos src/` → 0 resultados huérfanos.

[P0-3] Inputs no sincronizados (mezcla controlled / uncontrolled)
  Archivos: src/components/style_editor/InputNumber.jsx, InputSelect.jsx
  Problema: usan `defaultValue` (no controlados) mientras InputColor usa
            `value` (controlado). Si el estado cambia por código (reset,
            presets, URL, undo), los number/select NO se actualizan.
  Riesgo:  además, un número vacío produce `font-size: ""em` → estilo roto.
  Acción:  pasar todo a controlado (`value` + onChange) y validar/clamp del
           valor (min/max/step) antes de escribirlo al contexto; manejar el
           caso de entrada vacía (mantener último valor válido).
  Criterio: limpiar un number input y desenfocarlo no rompe el preview ni el
            código generado; cambiar el estado desde un preset actualiza todos
            los inputs.

[P0-4] Doble fuente de verdad en el código generado + sin escape de HTML
  Archivo: src/components/Salida.jsx
  Problema a: el string HTML+CSS se construye a mano con template literal
              duplicando los estilos reales del preview → si cambia un estilo
              y se olvida actualizar la plantilla, preview y salida divergen.
  Problema b: se copia leyendo `document.getElementById('codigo').textContent`
              (DOM como fuente de verdad) en vez de generar el string desde el
              estado.
  Problema c: el texto del usuario se inyecta SIN escapar. Un texto con `<`,
              `>` o `&` rompe (o inyecta marcado en) el snippet copiado.
  Acción:   crear src/lib/generateCode.js con una única función
            `generateCode(texto, estilos) -> string`, que:
              - derive el CSS de las MISMAS variables que usa el preview,
              - escapen `& < > " '` en el texto,
              - sea usada TANTO para el <pre> como para clipboard.writeText.
  Criterio: escribir `<script>alert(1)</script>` en el preview genera snippet
            escapado; no existe ningún valor de estilo duplicado en plantilla.

[P0-5] Timer sin limpieza (setState tras unmount)
  Archivo: src/components/Salida.jsx (setTimeout de 3000 ms en copiarCodigo)
  Problema: no hay clearTimeout ni guard de montaje → warning de React y posible
            fuga si se desmonta el componente.
  Acción:  guardar el id en useRef, limpiar en useEffect cleanup.
